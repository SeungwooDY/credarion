# Security & Engine-Integrity Review — 2026-07-26

Scope: authz on newer reconciliation endpoints, known-open items from the
2026-07-10 review (CSRF/CORS, session revocation), silent row-loss in
ingestion, and stats integrity in the reconciliation orchestrator.

## Fixed on this branch

### 1. Session revocation (medium) — FIXED
Tokens were stateless HS256 JWTs valid until expiry regardless of password
changes; a stolen cookie survived a password rotation.

Fix: session tokens now carry a `pfp` claim — a SHA-256 fingerprint of the
stored scrypt hash (`backend/app/security.py: password_fingerprint`).
`get_current_user` (backend/app/auth_deps.py) rejects tokens whose `pfp`
does not match the user's current hash, so a password change instantly
revokes every previously issued session. `/auth/change-password`
(backend/app/routers/auth.py) re-issues a fresh cookie so the active session
survives. Deactivating a user (`is_active=False`) already revoked sessions.

Note: deploying this signs out all existing sessions once (old tokens lack
`pfp`). That is intentional fail-closed behavior.

### 2. Tenant isolation on newer endpoints — VERIFIED + regression-locked
`GET /reconciliation/mismatches` and `GET /reconciliation/dashboard` take
`org_id` as a query param and perform no in-handler authz, but the
router-level `enforce_org_scope` dependency (backend/app/main.py:32-45,
backend/app/auth_deps.py:148-161) validates any path/query `org_id` against
the caller's account. `/annotated-statement` calls `authorize_supplier`
(backend/app/routers/reconciliation.py:815). ERP upload with
`replace=true` (destructive purge) calls `authorize_org`
(backend/app/routers/erp.py:56,103); statement upload replace calls
`authorize_supplier` + period-lock check (backend/app/routers/statements.py:232-233).

All confirmed enforced; regression tests added in
backend/tests/test_reconciliation_tenant_isolation.py
(cross-tenant dashboard org_id, mismatches, annotated-statement, and
erp replace upload).

## Verified acceptable (no change)

### 3. CSRF / CORS (low)
- No `CORSMiddleware` is installed, so the browser default same-origin
  policy applies: no cross-origin reads, and non-simple cross-origin
  requests fail preflight.
- The session cookie is `HttpOnly` + `SameSite=Lax`
  (backend/app/routers/auth.py:51-60), which blocks cookies on cross-site
  POSTs — the classic CSRF vector. All mutating endpoints are POST/PUT.
  Mutating GETs do not exist (exports are read-only downloads).
- Production forces `Secure` cookies and rejects the default signing key at
  startup (backend/app/config.py:34-50).

Residual (accepted for now): if CORS is ever opened for a separate frontend
origin, add an explicit CSRF token or switch to `SameSite=Strict` +
`Origin` header validation for mutating routes.

### 4. Ingestion row-loss accounting
Both pipelines count and surface skipped rows:
- GRN: `rows_skipped` / `rows_duplicate` / `rows_replaced` returned by
  `/erp/upload` and the SSE stream (backend/app/ingestion/grn_ingestor.py:377-382,
  backend/app/routers/erp.py:73-87,131-141).
- Statements: cleaning drops and per-row failures both land in
  `rows_skipped` (backend/app/ingestion/statement_ingestor.py:169-171,213-219)
  and are returned by `/statements/upload`.
- The ingestion UI displays ingested/skipped
  (frontend/app/ingestion/page.tsx:114-115,192-193).
- Column-mapping LLM failures degrade to `needs_review` (202), never to
  silent partial ingestion.

### 5. Orchestrator stats (ADR-0001 class)
`_compute_run_stats` (backend/app/reconciliation/orchestrator.py:330-372)
counts DISTINCT matched statement lines, discrepancies only on group primary
rows, and uses the two-sided denominator (combined statement lines +
missing-from-statement receipts) with a defensive 100% cap. Pre-aggregation
group stamping (orchestrator.py:764-774) keys strictly on the group primary
line id; the annotated export fans group verdicts out via
`stmt_combined_line_ids` with `setdefault` so a line's own result wins
(backend/app/routers/reconciliation.py:856-876). No double counting found;
covered by test_recon_routing_stats / test_preaggregate / test_multi_delivery.

## Deferred findings (not fixed here)

### D1. Failed runs can persist partial results (low, integrity)
backend/app/reconciliation/orchestrator.py:800-805 — on exception the
handler sets `run.status="failed"` and commits; any results already added
via `db.add_all(all_results)` (line 777) in the same session are committed
with the failed run. Read paths filter on `status == "completed"`, so the
rows are inert, but they are orphan noise and inflate raw result queries
that filter only by run_id. Proposed: `db.expunge_all()`/rollback of
pending result objects before the failure commit.

### D2. `/mismatches` `total_matches` counts result rows, not lines (info)
backend/app/routers/reconciliation.py:1055 — with `include_matches=true`,
aggregation-layer constituent rows (ERP-only members of a group) are each
counted as a "match", so `total_matches` can exceed the run's
`matched_count` (distinct statement lines) and disagree with `match_rate`.
UI/export display inconsistency only; stats stored on the run are correct.
Proposed: count distinct statement_line_ids, mirroring `_compute_run_stats`.

### D3. Unauthenticated static test page at `/` (low)
backend/app/main.py:53-57 serves `app/static/upload.html` with no auth. The
page itself only reveals API shape (all APIs it calls require a session),
but it is a leftover dev tool. Proposed: remove or gate behind auth in
production.

### D4. Reconciliation DEBUG logging in production (low)
backend/app/main.py:24-25 forces `app.reconciliation` to DEBUG, logging PO
numbers, material codes and amounts. Log access = customer data access.
Proposed: gate on `settings.is_production`.

### D5. `rows_skipped` conflates expected and unexpected drops (info)
backend/app/ingestion/statement_ingestor.py:171,219 — summary-row drops
(合计/小计, expected) and per-row parse failures (unexpected data loss) are
merged into one counter. An accountant cannot tell "3 summary rows removed"
from "3 data rows failed to parse". Proposed: separate counters or an
errors[] entry when row_errors > 0.

### D6. Session TTL / logout (info)
Logout only clears the cookie client-side; a captured token stays valid
until `exp` (24h) unless the password is changed. Acceptable for the
current threat model; full server-side revocation would need a session
table or token-version column.
