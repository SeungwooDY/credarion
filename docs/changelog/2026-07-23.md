# Changelog — 2026-07-23

Accountant-review features, batch 1: annotated statement export + configurable
date tolerance (match-with-note).

## Annotated statement export

The accountant's real workflow is to mark discrepancies ON the supplier's
statement and send it back. New export reproduces that:

`GET /api/v1/reconciliation/annotated-statement?supplier_id=&period=` returns
the supplier's original statement .xlsx with two columns appended (对账结果 /
备注) carrying the latest run's outcome per row — 相符 ✓, 差异 ✗ with delta
notes (数量差异/单价差异/金额差异 + any human flag reason), 已核实 ✓ for
resolved false positives. ERP receipts missing from the statement are appended
as a highlighted section below the data so the supplier can carry them into
next month's statement. Frontend: "Export Annotated Statement" button above
the review queue (`frontend/app/reconciliation/page.tsx`).

Supporting changes:
- **Durable statement storage** — uploads previously went to a throwaway
  temp file and `supplier_statements.file_url` pointed at it; originals were
  lost on restart. Uploads now persist under `settings.statement_upload_dir`
  (`uploads/statements`, reusing `app/invoicing/file_storage.save_upload`),
  and `original_filename` is recorded.
- **`statement_line_items.source_row`** — 1-based Excel row of each line in
  the original file, captured at ingestion (before cleaning drops/reindexes
  rows), so annotations land on the exact rows the supplier sent. Helper
  columns (`_source_row`) are excluded from `raw_row`.
- **Rebuild fallback** — statements ingested before durable storage (or
  .xls/.csv uploads) get a reconstructed sheet from each line's `raw_row`
  audit copy instead of the in-place annotation.
- New module `backend/app/reconciliation/annotate.py`.

## Date tolerance (± days, match-with-note)

Accountant guidance: ERP grn_date vs statement delivery_date gaps are not a
problem as long as quantity and amount agree. New org-level config
`reconciliation_config.date_tolerance_days` (default 3, editable in Settings):

- Within the window: nothing changes.
- Beyond the window on a 1:1 match: the match is kept — an exact match moves
  to the near_exact attention queue labelled "Match — Date Mismatch" with an
  explanatory note; near_exact/fuzzy/ai matches get the note appended. A date
  gap alone is never classified as a discrepancy.

Wired through `_load_config` → `_match_to_result` → `_classify_review`
(`backend/app/reconciliation/orchestrator.py`), the config API
(`ConfigUpdate`/`ConfigResponse`, `/config/{org_id}`), and the Settings page.
