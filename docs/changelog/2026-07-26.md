# Changelog — 2026-07-26

Accountant-review features, batch 2: statement-side pre-aggregation (strict
all-columns rule) + dashboard/mismatch UI refinements from Richard.

## Statement-side pre-aggregation

Supplier statement lines are combined into one line BEFORE matching, but only
under the strictest rule: **every identifying column must be identical** —
same PO number (normalized), same material number, same delivery date, same
delivery note ref, and same per-unit price. If the PO or the date (or
anything else) differs, lines stay separate. Quantity and amount are summed;
`unit_price` stays per-unit and is never aggregated.

- New module `backend/app/reconciliation/preaggregate.py`
  (`combine_statement_lines`), run in the orchestrator right after statement
  items are loaded. `run.total_statement` counts combined lines so the match
  rate stays consistent.
- Results referencing a combined group's primary line carry
  `match_details.stmt_combined_lines / stmt_combined_line_ids /
  stmt_combined_qty / stmt_combined_amount`.
- `/reconciliation/mismatches` shows the combined qty/amount on the statement
  side (deltas were computed against those totals, so the row now adds up).
- Annotated statement export fans the group verdict out to every raw supplier
  row, so each original line on the returned sheet gets a 对账结果.
- Note: with the strict key, the original "flag differing unit price as a
  discrepancy" sub-rule is moot — differing prices simply never combine and
  fall through to normal matching.

## Never round supplier decimals

Some suppliers quote prices to the 4th decimal place and beyond (e.g.
0.6575). These values must never be rounded, at any layer:

- **Storage (migration `0009_unconstrained_numeric_precision`)** — the
  line-level numeric columns on `erp_records`, `statement_line_items`, and
  `reconciliation_results` (quantities, prices, amounts, deltas) move from
  fixed scales (prices NUMERIC(12,4), amounts NUMERIC(14,2), quantities
  NUMERIC(14,3)) to unconstrained NUMERIC — Postgres stores exact values of
  any precision; widening is metadata-only. **Must be run on Render prod.**
- **Backend text** — discrepancy notes no longer format the price delta with
  `.4f`; the annotated export's delta formatter renders full precision with
  trailing zeros trimmed (`+0.6575` stays `+0.6575`, `+0.650000` → `+0.65`).
- **Frontend** — `formatNum`/`formatCurrency` on the mismatches page now
  treat their decimal count as a minimum (real decimals up to 10 always
  show); spreadsheet grid cap raised 4 → 10; reconciliation page drops
  `toFixed` for delta display.
