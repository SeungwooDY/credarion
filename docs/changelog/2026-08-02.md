# Changelog — 2026-08-02

Date is no longer a match criterion. A statement line pairs with any ERP
receipt sharing the same PO + material + unit price, regardless of how far
apart the two dates are; quantity remains the only field allowed to deviate
on a pair.

## Why

Richard's examples from the pilot data: the statement and the ERP record the
same physical receipt on different dates (e.g. supplier claims 03-17, GRN
posted 03-22), and under the old ±3-day gate those rows surfaced as a
missing/extra pair on each side instead of matching. Doc numbers likewise
differ between the systems and were already not part of the key.

## What changed (`exact_match.py`)

- `run_keyed_match` (shared by the exact and fuzzy layers) no longer rejects
  candidates whose date gap exceeds `date_tolerance_days`. The date gap is
  still computed and used to **rank** candidates — delivery-note match first,
  then smallest known date gap, then closest quantity — and is still recorded
  in `match_details.date_gap_days`.
- `date_tolerance_days` (config field, DB column, Settings input) is retained
  for compatibility but is now inert. Candidate for removal from the Settings
  UI later.
- Pre-aggregation is unchanged: same-side rows still combine only on
  identical (PO, material, unit price, date).

## Explicitly out of scope

Material numbers still compare as exact strings. Richard confirmed that
suffix variants like `590*5305*3*001` vs `590*5305*3*000` are different
materials and must NOT match, even when PO, qty, and price all line up.

## Tests

- `test_different_dates_still_pair` — 20-day gap, otherwise identical → matched.
- `test_delivery_note_match_beats_closer_date` — DN evidence outranks date
  proximity now that the date gate is gone.
- `test_closest_date_breaks_ties` — new: date still picks between
  otherwise-identical candidates.
- `test_rows_pair_across_dates` (orchestrator) — replaces
  `test_equal_totals_across_dates_are_not_netted`: cross-date rows with equal
  qty/price now pair 1:1 for a 100% rate.
- Full suite: 318 passed.
